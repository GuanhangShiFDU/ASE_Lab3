# 双角色界面与地图 · #71272992

## 启动与账号

在仓库根目录运行 `docker compose up -d --build --wait`，打开 `http://localhost:18080`。前端端口可通过 `FRONTEND_PORT` 调整。打开两个独立浏览器窗口，用「乘客一」和「司机一」登录。前端是 Vite 构建的静态应用，Nginx 提供页面和同源 API 代理。

- 登录和上下线走 [Driver](driver.md)，接单、拒单和邀约确认走 [Dispatch](dispatch.md)。
- 估价、叫车、取消、到达、上车和完单走 [Order](order-write.md)，状态、司机资料和乘客历史走 [Order Query](order-query.md)。内部服务接口不通过前端代理暴露。
- 浏览器约每两秒刷新订单。重试写请求时复用同一幂等键，收到成功写响应先显示最新状态；读侧暂缺或版本较旧时保留写入结果。接单请求收到 202 时显示确认中，轮询到确认才显示接单成功。刷新页面后用当前窗口保存的会话继续从后端查询。

## 地图

Leaflet 展示由预设 WGS84 坐标决定的起终点和连线。地图连线只表示两点关系，距离与费用由后端估算。默认底图由 OpenStreetMap 提供，页面保留署名和链接，请遵守[瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)。浏览器只请求当前视野的瓦片。

若瓦片全部失败或超时，页面切换到本地示意格网，仍展示起终点、坐标和订单信息。打开 `http://localhost:18080/?tiles=off` 可直接演示。也可设 `MAP_TILE_URL=off` 再构建前端，默认禁用在线底图。

## 验证步骤

1. 司机上线，乘客选两个不同地点，查看估价并叫车。
2. 司机接受邀约，双方看到接单确认、起终点和订单状态，乘客能看到司机姓名。
3. 司机点击到达、上车和结束；上车后乘客界面隐藏普通取消，刷新仍能找回当前行程，并能在完单后查看历史。
4. 再次叫车并在上车前取消，确认可重新叫车。
5. 在示意模式重复主流程，确认仍有起终点标记及坐标，业务操作可继续。
6. 运行 `npm --prefix frontend test`，检查投影延迟、重新叫车版本切换和不同角色的行程按钮。
