| 层级 | 启动范围 | 主要断言 |
| --- | --- | --- |
| 单元级 | Node 测试运行器。应用层用内存测试替身隔离存储。 | 估价及输入限制、角色与归属、创建使用认证身份、合法状态迁移、取消与完单规则、重复开始不再写入。 |
| 服务级 | Order 的实际 HTTP 处理器、应用层、仓储，及专用 Docker MySQL 8.4 测试库。 | 贯通健康、认证和估价，检查完整行程落库。并发使用相同幂等键只产生一单；重启 HTTP 后能重放原响应；同一司机竞争及取消与上车竞争均只提交一个结果。直接查询订单、幂等、释放任务和 Outbox 表确认数据库状态。 |

故障用例先在测试库占住下一条 Outbox 版本，触发真实唯一索引冲突。取消请求返回 503，订单仍处于接单状态，Outbox、幂等记录和释放任务没有残留半次提交。去掉故障后，同一取消键可以成功，取消结果、事件和释放任务一并落库。日志中的 `ER_DUP_ENTRY` 是本用例预期注入的故障。

测试环境由 [README](../README.md#order-自动化测试) 的命令创建与回收。服务级使用独立 Compose 项目、内存数据目录、专用 `lab3_order_test` 库及 Node 24 镜像；用测试签名凭证构造身份。测试覆盖 Order 的本地事务边界，真实 Driver、Dispatch、Order Query 和跨服务故障恢复由对应联调测试及现场验收覆盖。
